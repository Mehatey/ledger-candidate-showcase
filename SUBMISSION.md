## Brief coverage

| Brief asks for | Ledger response |
|---|---|
| Quickly understand what was built | Factual three-question strip, candidate explanation, metadata |
| Review without external tabs | Inline preview, README, screenshots, chaptered walkthrough |
| Candidate and role context | Candidate hero, challenge breadcrumb, profile rail |
| Frameworks and tools | Claimed versus repository-evidenced stack with inspectable provenance |
| Notes, scorecard, actions | Anchored four-part rubric, required reasons for low scores, decision gate, undo |
| Empty and error states | Missing demo, screenshots, walkthrough, failed deploy, already reviewed |
| Responsive thinking | Evidence-first stacking plus sticky mobile review dock |
| Component structure | `Card`, `RailCard`, `Empty`, `Tag`, config-driven `Rubric` |
| Product judgment | Focused verdict loop; no full recruiting platform |

## What is innovative

- Separates material completeness from work quality, reducing premature judgment.
- Turns tech-stack claims into inspectable repository evidence.
- Uses behaviorally anchored scoring rather than an ambiguous star rating.
- Treats broken infrastructure differently from absent work.
- Makes missing-material guidance useful to reviewer and candidate.
- Optimizes repeated review with keyboard controls, persistent drafts, and undo.
