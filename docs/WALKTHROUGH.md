# Ledger — Editorial showcase walkthrough (60–75 seconds)

This is an intentionally secondary exploration alongside the evidence-first workbench. Keep the tone direct: it is a different lens on the same candidate-review problem, not a competing product proposal.

## Spoken script

“For this second exploration, I kept the same candidate-review problem but gave it a more editorial, candidate-story treatment. Ledger brings the work into one reading surface so a reviewer can understand the person and the submission without tab switching.

“At the top, I reduced the profile to identity, role, status, and a short account of what was made. Submission timing, code volume, and the challenge context move into the adjacent review context, so the page has one clear reading order instead of repeating the same person information on both sides.

“The first strip answers three factual questions: what they built, whether it runs, and what evidence exists. Then the Vantage prototype plays inline, followed by the candidate’s README. Screenshots, walkthrough, and tooling stay on the same page but open only when useful.

“The review rail keeps the decision close to the work. It separates evidence from candidate claims, uses anchored scoring instead of a vague star rating, and treats a missing or failed submission artifact as a specific state rather than silently penalising the candidate.

“On mobile, the evidence stays in reading order and the scorecard and decision remain reachable from the compact dock. Motion is restrained: candidate changes, evidence disclosure, and controls give feedback, while reduced-motion preferences remove nonessential movement.

“This is the narrative, atmospheric counterpart to the evidence-first workbench: same functional core, but a more authored way to read a candidate’s work.”

## Capture path

1. Start on the showcase.
2. Open Siddharth / Vantage.
3. Point out the simplified header, three-question strip, and inline prototype.
4. Expand Stack and tooling once, then show Tomás’s failed-preview state.
5. Resize to mobile and show the scorecard / decision dock.

Target: 65 seconds. Do not open the design-system view or narrate every state.
